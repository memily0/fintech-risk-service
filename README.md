# ArcShift 2.0 — fintech risk service

ArcShift 2.0 — развиваемая система для исследования индикаторов финансового риска и их последующего использования в продуктовом сервисе. Сейчас репозиторий содержит существующий аналитический Streamlit-дашборд и скрипт подготовки его датасета. Каркас для будущих исследований, моделей и сервисных компонентов подготовлен, но эти части ещё не реализованы.

## Research и Product

- **Research** (`research/`) — будущие исследования P1/P2, воспроизводимые эксперименты и проверенные результаты.
- **Product** (`app/`) — пользовательский интерфейс, сервисы и переиспользуемые UI-компоненты.
- **Models** (`models/`) — будущий код обучения и инференса, а также управляемые артефакты моделей.
- **Data** (`data/`) — источники, промежуточные наборы и подготовленные данные.

Исследования P1/P2 пока ведутся отдельно в `qu1nty9/arcshift-research`. Этот репозиторий не копирует и не изменяет их содержимое.

## Структура

```text

├── app/
│   ├── dashboard.py          # существующая точка запуска Streamlit
│   ├── dashboard/            # будущие страницы и логика дашборда
│   ├── services/             # будущие прикладные сервисы
│   └── components/           # будущие UI-компоненты
├── configs/                  # конфигурации без секретов
├── data/
│   ├── raw/                  # неизменённые выгрузки из источников
│   ├── processed/            # воспроизводимые преобразованные данные
│   ├── external/             # внешние данные с подтверждёнными правами
│   └── README.md             # происхождение и правила хранения данных
├── docs/                     # проектная и архитектурная документация
├── models/
│   ├── training/             # будущие пайплайны обучения
│   ├── inference/            # будущий код прогнозирования
│   └── artifacts/            # локальные/управляемые артефакты
├── research/
│   ├── p1_model_comparison/
│   ├── p2_feature_research/
│   ├── experiments/
│   └── results/
```

Существующие `data/moex/`, `data/yahoo/`, CSV в корне `data/` и `app/dashboard.py` оставлены на прежних путях, чтобы не нарушить текущие сценарии. Их перенос должен выполняться отдельным изменением вместе с обновлением путей и тестов.

## Быстрый старт

Требуется Python 3.11 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
streamlit run app/dashboard.py
```

Дашборд читает уже находящийся в репозитории `data/final_dataset.csv`.

Сборщик датасета запускается отдельно и обращается к внешним источникам:

```bash
python scripts/build_final_dataset.py
```

Перед запуском ознакомьтесь с [описанием данных](data/README.md): сборщик перезаписывает `data/final_dataset.csv` только после встроенной валидации, а доступность внешних источников не гарантируется.

Локальные проверки структуры и синтаксиса:

```bash
python -m compileall -q app scripts tests
python -m unittest discover -s tests -p "test_*.py"
```

## Командная разработка

`main` содержит только проверенный интегрированный код. Направления работы документируются префиксами `feature/data`, `feature/models`, `feature/research` и `feature/product`; это не четыре независимые версии проекта. Изменения попадают в общий `main` через небольшие Pull Request после CI и ревью. Полные правила описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

## Будущая интеграция исследований

Интеграция `qu1nty9/arcshift-research` начнётся только после отдельного ревью и решения о составе переносимых материалов. Предполагаемый порядок:

1. Зафиксировать версии, лицензии, происхождение данных и критерии воспроизводимости.
2. Выбрать проверенные P1/P2-эксперименты, не перенося историю вслепую.
3. Разместить исследовательский код и результаты в соответствующих каталогах `research/`.
4. Вынести стабильный код обучения и инференса в `models/`, сохранив тестируемую границу с исследовательскими ноутбуками.
5. Подключать модели к продукту только отдельным Pull Request после валидации риск-аналитиком.

До такого решения исследовательский репозиторий остаётся самостоятельным источником и не является зависимостью текущего приложения.
