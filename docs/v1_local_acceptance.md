# Локальная приёмка ArcShift V1

Прогон 09.11.2026. Проверена отдельная временная копия `v1/integration-yaroslav`
на базе `59ba4a71a8eb60bb1f990ea54006cf4ac9385435` с текущими локальными
изменениями методики, UI и проверок. Оба Python-окружения созданы с нуля,
установка выполнена по репозиторным lock-файлам. Прогон относится к этому
локальному состоянию; опубликованный SHA сам по себе его не воспроизводит.

Новый сценарий `tools/smoke_v1_auth.py` по HTTP регистрирует два `.test`-аккаунта,
читает историю USD/RUB и сохраняет её вместе с первой версией разбора. После
редактирования и перезапуска он сверяет новую версию разбора и неизменный
отчёт. У владельца открываются PDF/CSV/JSON. Второй пользователь с активной
сессией получает `404` на карточке и во всех трёх форматах. Cookie владельца
сначала подтверждает его личность, а после logout с этим же cookie запрос
на PDF получает `401`. Временные БД и серверы очищаются, письма остаются в
локальном тестовом outbox.

Проверен состав wheel. В нём есть runtime-модули, синтетические fixtures,
миграции, статика и шрифт с лицензией. Датасеты, веса, рабочие БД и приватные
исследовательские файлы отсутствуют. SHA-256 проверенного wheel
`d399724f34ea799402f0b2088b62329edf21d0e9ea9f26fc328b5d22180766c8`.
Хеш идентифицирует этот файл; побайтовая воспроизводимость wheel не проверялась.

## Повторный прогон

В свежем checkout проверяемого коммита, из корня репозитория:

```sh
python3.14 -m venv .venv-v1
.venv-v1/bin/python -m pip install -r requirements-v1.lock
.venv-v1/bin/python -m pip install --no-build-isolation --no-deps -e .
.venv-v1/bin/python -m pip check
.venv-v1/bin/python -m unittest discover -s tests -q
.venv-v1/bin/python tools/smoke_v1_backend.py
.venv-v1/bin/python tools/smoke_v1_auth.py

python3.14 -m venv .venv-validation
.venv-validation/bin/python -m pip install -r requirements-validation.lock
.venv-validation/bin/python -m pip check
.venv-validation/bin/python -m unittest discover -s tests/model_validation -q
```

Для браузерного прогона нужен Node с Playwright в пути модулей. С установленным
Chrome команда `ARCSHIFT_PLAYWRIGHT_CHANNEL=chrome node tools/smoke_v1_workbench.cjs`.
С настроенным Chromium Playwright достаточно `node tools/smoke_v1_workbench.cjs`.
`ARCSHIFT_BROWSER_EVIDENCE_DIR` позволяет сохранить синтетические снимки экрана
и примеры PDF в отдельный локальный каталог.

Режимы проверяются раздельно. Для проверки дистрибутива собрать wheel командой
`.venv-v1/bin/python -m pip wheel --no-build-isolation --no-deps --wheel-dir dist .`,
установить его в новое окружение с тем же runtime lock и запустить копии двух
Python-smoke из каталога вне исходников. Полный набор исходных unit-тестов
требует `-e .`: запуск с установленным wheel выявил два `FileNotFoundError`
в тестах, которые загружают checkout-реестр через путь по умолчанию. После
установки `-e .` оба прошли. API из wheel использует вложенный реестр через
явный путь и прошёл HTTP-проверку. Starlette предупреждает о deprecated
интеграции TestClient с HTTPX; предупреждение сохраняется в выводе тестов.

## Границы приёмки

Локальное покрытие относится к A01/A04 (тестовая регистрация и отзыв сессии),
A07/A09/A11 (часть рабочего процесса, история и неизвестное время публикации),
A17–A19 (синтетические временные ограничения и недоступный прогноз),
A27/A31 (отчёт и изоляция). Из A39 проверены три ширины экрана; сценарий
клавиатуры и 200% размера текста в этот прогон не входил. Сверка истории
и отчёта выполнена с одним активным market snapshot; смена активного снимка
между запросами остаётся отдельным сценарием.

G04 получил локальное подтверждение установки и запуска на macOS. Release
gate остаётся `pending` до повторения на зафиксированном релизном коммите.
Проверки не покрывают эксплуатационные нормативы, нагрузку, восстановление
из резервной копии, staging или допуск данных и модели.
